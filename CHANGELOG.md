# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project will adhere to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) once a numbered release is cut.

## [Unreleased]

### Added
- **Setup Wizard — Cameras step.** First-run users can now discover and register IP cameras during the Setup Wizard alongside Android devices. Single `Scan Network` button auto-detects the LAN subnet via `SubnetDetectionClient` (which calls ws-scrcpy-web's `/api/devices/scan/subnet` endpoint to find the adapter with a default gateway in the same subnet) and runs ONVIF-only WS-Discovery — no TCP-554 RTSP sweep, mirroring how WizardDevices uses mDNS-only quick discovery instead of full sweeps. Discovered ONVIF cameras stream into the existing `DiscoveredCamerasPanel` (shared with Settings → Cameras): inline Add per row, optional shared-creds entry above the grid for fleets with one admin password. Registered cameras render in a small Cam # / Name / Mfr-Model / Address summary table at the bottom of the step. WizardDone summary surfaces the camera count alongside the device count. Non-ONVIF / RTSP-only cameras are deferred to Settings → Cameras post-wizard via a clearly worded help note in the step intro.
- `ICameraScanService.StartOnvifOnlyScanAsync(IReadOnlyList<ParsedSubnet>, CancellationToken)` — new ONVIF-only scan entry point. Same `Phase` transitions, event bus, and `Hits` accumulation as `StartScanAsync`, but skips the parallel TCP-554 sweep branch. Implemented by factoring the existing `StartScanAsync` body into a private `RunScanAsync(subnets, includeRtspSweep, ct)` helper; `StartScanAsync` is now a thin wrapper with `includeRtspSweep: true`, preserving all existing behavior bit-for-bit.
- `WizardState.CamerasAdded` for the Done-step summary line.
- **Background liveness probing for cameras and Android devices.** Two new hosted services (`CameraLivenessHostedService`, `AndroidLivenessHostedService`) periodically TCP-probe each registered camera (RTSP port) / device (ADB port) and bump `LastSeen` on success — keeping the Status dot accurate without user-initiated scans. Liveness path is per-target direct probing, not a subnet sweep, so the Discovered panel is **never** populated by the background loop (manual Scan Network is the only path that fills Discovered). Hot-reload via a new `IntervalChangeSignal` singleton: editing the interval in Settings breaks the service out of its outer Task.Delay so the new cadence takes effect immediately rather than after the current delay window.
- **Liveness Interval setting on `Settings → Cameras`** (top of page). New `cameras-liveness-interval-seconds` config key. Allowed values: `0` (disabled) or `300–3600` seconds. Default `300` (matches Android Devices default).
- **Restore Default button** next to the Liveness Interval input on both `Settings → Cameras` and `Settings → Android Devices` — one click resets to `300s` and triggers immediate hot-reload of the corresponding hosted service.
- **Scan Now button** between the Liveness Interval input and Restore Default on both pages. Click triggers an immediate liveness tick (refresh Status/LastSeen for every registered target) without waiting for the next periodic cadence. Reuses the existing `IntervalChangeSignal` plumbing — no new infrastructure.
- **`Settings → Cameras` Quick Scan button.** Mirrors the Android Devices page's Quick Refresh / Scan Network split. Quick Scan auto-detects the LAN subnet via `SubnetDetectionClient` and runs `ICameraScanService.StartOnvifOnlyScanAsync` directly — fast (~3-5s), ONVIF only, no modal. The existing Scan Network button stays untouched (full ONVIF + TCP-554 sweep with subnet selection modal). Toolbar order: Quick Scan (secondary) | Scan Network (primary) | Add Camera Manually | Delete All. Intro paragraph updated to differentiate the two scan paths.
- Newly-added cameras seed `LastSeen = DateTime.UtcNow` on insert (`CameraService.AddAsync`) so freshly-registered cameras don't render as "Never" while waiting for the first liveness tick to land on them.
- **Configurable Jellyfin backup and log directories.** New `jellyfin-backup-directory` and `jellyfin-log-directory` settings on the Jellyfin Settings page (Logging, Backup & Retention section). Empty value falls back to the derived defaults under `AppContext.BaseDirectory`. Saving a new path best-effort-migrates existing `*.db` (Backups) or `*.log` (Logs) files; per-file failures (e.g., locked active log files on Windows) surface in the standard notification with a "Retry the Save to migrate them" hint.
- **Reusable Settings grid components** (`SettingsSection`, `SettingsGrid`, `SettingsGridCell`) under `Components/Shared/Settings/`. Two-column grid pattern with optional Label / Hint slots and FullRow span. Adopted by General Settings and Jellyfin Settings; available for future settings pages.
- **External Dependencies section** on Settings → General. New section replaces the old "ws-scrcpy-web deployment" toggle. Two full-row configurable inputs: ws-scrcpy-web URL (always external; user runs the instance) and Docker executable directory path (writes to `dep-path-docker`, picked up by the existing dep-path override mechanism so the Dependencies page shows actual installed Docker version). Section intro paragraph notes that scanning features depend on a running ws-scrcpy-web instance.
- **Docker version probe — Installed and Latest** on the Dependencies page. Docker dep registration now declares an `InstallPath` so the version-probe pipeline runs `docker --version` against the user-configured path (Installed column). New `VersionCheckUrl` against the moby/moby GitHub releases API populates the Latest column. The version-check dispatch now runs `CheckDirectUrlVersionAsync` for any dep with `VersionCheckUrl` set, regardless of `SourceType`. Update button is suppressed for docker (and ws-scrcpy-web) — both deps are externally managed, so even when Status flips to Update Available the row only shows Check + project link.

### Fixed
- **GitHub API requests now include a `User-Agent` header.** `dependency-updates` and `github-api` named HttpClients default to `User-Agent: ControlMenu`. Without this, GitHub returns HTTP 403 — which silently failed the docker version-check (and would have affected any future `api.github.com` calls from the dep-update path).
- **moby/moby tag_name regex** matches the actual `docker-v29.4.2` tag format (was looking for `v29.4.2` and never matching).
- **Stale `external` placeholder in `Dependencies.InstalledVersion`** for the ws-scrcpy-web row is cleared on every boot by the obsolete-settings cleanup hosted service. Pre-T1 code wrote the literal string "external" into that field; the dependencies page now also force-renders `—` for ws-scrcpy-web Installed / Latest until the v0.5.0 cross-check (see ws-scrcpy-web project memory §15).
- **`Settings → Android Devices` now refreshes Status / Last Seen in-place after a liveness tick.** `DeviceManagement.razor` previously only subscribed to `IScanLifecycleHandler.OnStateChanged` (scan-lifecycle events), not `IDeviceChangeNotifier.Changed` (DB-mutation events). When `AndroidLivenessHostedService.UpdateLastSeenAsync` fired the singleton notifier, no consumer on the page was listening — events fanned out to zero subscribers and the grid stayed stale until manual page refresh. Page now subscribes to the notifier in `OnInitializedAsync`, marshals to the UI thread + `LoadDevices` + `StateHasChanged` in the handler, unsubscribes in `Dispose` — mirroring the working `CameraSettings.razor` pattern.
- **Scan-event subscribers handle `ObjectDisposedException` from `InvokeAsync` after disposal.** `ICameraScanService` is a singleton whose `Emit` fan-out can invoke a subscriber callback after the consumer component has disposed. The fire-and-forget `_ = InvokeAsync(...)` previously swallowed the resulting `ObjectDisposedException` as an unobserved task exception. `DiscoveredCamerasPanel.HandleEvent` and `WizardCameras.OnScanEvent` now wrap the `InvokeAsync` call in `try/catch (ObjectDisposedException)` to make the swallow explicit and avoid framework-level unhandled-task-exception logging.
- **WizardCameras subnet-detect failure message** previously said only "Could not auto-detect a network subnet" — accurate but not actionable. The most common cause of `SubnetDetectionClient.DetectAsync()` returning null is ws-scrcpy-web being down (the endpoint lives there). New message: "Could not auto-detect a network subnet — verify ws-scrcpy-web is running. You can also add cameras manually from Settings → Cameras after setup completes."
- **`DiscoveredCamerasPanel` no longer surfaces just-registered cameras as still-discoverable across navigation.** `ICameraScanService` is a singleton whose `_hits` list persists from the most recent scan until the next one starts. When the wizard's Discovered panel was used to Add cameras and the user then navigated to `Settings → Cameras`, the new panel instance mounting there bootstrapped from the singleton's still-populated `Hits` and re-rendered the just-registered cameras as if discoverable — they wouldn't clear until another scan ran. The panel's bootstrap path now filters `ScanService.Hits` against `CameraService.GetAllAsync()` before populating its local list, so any camera already in the DB is excluded from the initial Discovered render. Subsequent scan events still flow through unchanged.

### Changed
- **Settings sub-nav order: Cameras moved up to second slot** (after Android Devices, before Jellyfin). Settings sub-nav now reads General → Android Devices → Cameras → Jellyfin → Dependencies. Home page Settings card pills match the new order.
- **Toolbar parity between Settings → Android Devices and Settings → Cameras.** Both pages now expose the same shape: `[+ Add ___ Manually]` (green/primary, first) → `[⚡ Quick Scan…]` (transparent/secondary) → `[📡 Scan Network…]` (transparent/secondary) → `[🗑 Delete All]` (red, when ≥1). Specific changes:
  - Android: `Add Device` → `Add Device Manually`. `Quick Refresh` → `Quick Scan…` (icon `bi-arrow-clockwise` → `bi-lightning-charge`; same `QuickRefresh()` handler — mDNS scan + ARP reconciliation behavior unchanged, just rebranded for parity).
  - Cameras: toolbar reordered with `Add Camera Manually` promoted to the first position and styled `btn-primary` (was `btn-secondary` outline). `Quick Scan` → `Quick Scan…`. `Scan Network` → `Scan Network…` and demoted from `btn-primary` to `btn-secondary` so both scan buttons render identically across pages.
  - Both `Quick Scan…` buttons use the lightning-bolt icon (`bi-lightning-charge`) — visual cue that both paths are "fast protocol-native discovery" (mDNS for Android, ONVIF WS-Discovery for Cameras).
- **Camera network scanner + DB-backed camera CRUD** (resolves TODO item 10). New `Settings → Cameras` page replaces the indexed 8-slot panel. Cameras now live in their own `Cameras` table with full CRUD; manage Add/Edit/Delete/Enable from the UI; deletion cleans up associated secrets. Stream key in `go2rtc.yaml` changed from `camera-{1..N}` to `camera-{guid:N}`. New scan flow: ONVIF WS-Discovery probe (multicast UDP 3702) finds ONVIF-conformant cameras with manufacturer/model auto-populated; TCP-554 sweep finds non-ONVIF RTSP cameras; both run in parallel against the same subnet list. WS-Discovery probe is hand-rolled (per-interface UDP socket binding + SOAP envelope + XML response parsing) — the original `OnvifDiscovery` NuGet was dropped because its automatic interface enumeration silently skipped the user's `vEthernet (Local Area Network)` Hyper-V virtual switch, which is bridged to the physical NIC where the cameras live. Discovered panel: ONVIF rows take inline username/password and validate by `GetStreamUri` (with optional bulk-creds entry above the grid for fleets sharing creds); non-ONVIF rows open a fuller modal with stream path + RTSP `DESCRIBE` validation. Periodic background re-scan every 15 min (configurable via `cameras-scan-interval-minutes`, `0` = off). Subnet selection mirrors the Android scanner — auto-detect via `SubnetDetectionClient`, user adds more via `ScanNetworkModal`, large-subnet warning via existing `LargeSubnetWarningModal`. ONVIF SOAP (3 verbs: `GetDeviceInformation`, `GetProfiles`, `GetStreamUri`) hand-rolled with WS-Security UsernameToken digest auth.
- **Hikvision/LTS-OEM ISAPI integration** (post-Add enrichment for the camera scanner). After ONVIF Add succeeds, fires a best-effort `GET /ISAPI/System/deviceInfo` against the camera. If the response parses as Hikvision-firmware DeviceInfo XML, populates Camera Number (from `<telecontrolID>`), MAC address (from `<macAddress>`, normalized to dash convention), and overrides the auto-filled Name with `<deviceName>` (the user-set "Device Name" from the camera's web UI — e.g. "Front Porch", "Garage") UNLESS the user manually edited the Name field before clicking Add. Behavior-based vendor detection (no hardcoded brand list) — works for Hikvision, LTS, Honeywell Performance, W Box, Annke, and every other OEM rebrand of Hikvision firmware on the market. Auth uses `HttpClientHandler` + `NetworkCredential` + `PreAuthenticate=false` so HttpClient does challenge-response and supports both Basic (V5.7+ firmware) and Digest (V5.6.x firmware). Non-Hikvision-firmware cameras silently skip enrichment.
- **Camera grid display fields promoted to typed columns.** `Camera` entity gained `MacAddress`, `CameraNumber`, `FirmwareVersion`, `SerialNumber`, `HardwareId` columns; the speculative `Metadata` JSON column was removed. EditCameraModal Device Info section reads typed columns directly. Configured-cameras grid sorted by Camera Number ascending (nulls last), shows columns: Status / Cam # / Name / Mfr / Model / Address / MAC / Enabled / Last Seen / Actions.
- **Bulk Delete All on Cameras and Devices settings pages.** New red "Delete All" toolbar button on each page (only rendered when ≥1 row); confirm dialog; atomic batch delete with single change-notifier fire (avoids N regen storms on Cameras side). For Devices, the per-MAC name-stash that single-Delete uses for re-discovery is intentionally skipped on bulk delete (bulk = wipe-state intent).
- **`feat(a5)`** Per-device scrcpy stream settings modal on all device dashboards. "Stream Settings" in quick-actions opens a settings modal (video codec, encoder, bitrate, max FPS, max resolution, audio toggle, audio source, audio codec) with probe-driven smart defaults from ws-scrcpy-web's device probe. Settings persist in the database and are passed to ws-scrcpy-web as URL params on the embed iframe. First visit probes the device automatically with a 3-second grace period before connecting — single clean connection, no double-connect. Three modal buttons: Save (persists without reconnecting, stays open), Connect (applies settings and reconnects, closes modal), Clear/Refresh (re-probes device for updated capabilities, stays open). Two-column grid layout matching ws-scrcpy-web's ConfigureScrcpy modal.
- **Android Power Tools module** (new, sort order 2, sits between Android Devices and Jellyfin in the sidebar). Hosts ws-scrcpy-web's full home page via iframe at `/android-power-tools` — one-click shell (xterm), file browser (ListFilesModal), stream configuration, network scan + manually-add-device panel, and dependency updater. Peer of the Android Devices module, not a replacement — the existing device management surface (registered-devices list, PIN unlock, power state, sleep/wake, screensaver, Projectivy backups) stays untouched. Module declares no dependencies of its own (inherits ws-scrcpy-web from AndroidDevices). Fallback: if `WsScrcpy.IsRunning` is false, shows a warning alert instead of a broken iframe.

- `DeviceType` enum gained `AndroidTablet` and `AndroidWatch` alongside the existing `GoogleTV` / `AndroidPhone`. Persisted as string via EF so existing rows are untouched; no migration needed. Tablet and watch devices don't yet get a dedicated dashboard, but they're first-class in the Device Management table and the mDNS scan auto-classifier.
- `ScrcpyMirror.razor` gained an optional `DeviceKind` parameter (`"phone"`, `"tablet"`, or `"tv"`). When set, it's forwarded to ws-scrcpy-web's `/embed.html` as `&deviceKind=<value>` so the stream toolbar's D-pad/Touch input-mode toggle seeds the right default. `GoogleTvDashboard.razor` passes `"tv"` (D-pad default); `PixelDashboard.razor` passes `"phone"` (Touch default). Requires ws-scrcpy-web commit `6f217cd` or later, which wires the URL param through in `embed-entry.ts`.
- `IAdbService.ScanMdnsAsync()` returns a list of `MdnsAdbDevice` records (service name + IP + advertised ADB port) by parsing `adb mdns services`. Uses a direct port of ws-scrcpy-web's tab-split `parseMdnsOutput` for robustness.
- `IAdbService.DetectDeviceKindAsync(ip, port)` classifies an Android device as `"phone"`, `"tablet"`, `"tv"`, or `"watch"` using five parallel shell probes (`ro.build.characteristics`, `pm has-feature android.software.leanback`, `pm has-feature android.hardware.type.watch`, `wm size`, `wm density`). Mirrors ws-scrcpy-web's four-signal `classifyDeviceKind` plus a fifth watch-feature probe for Wear OS support. Watch precedence > TV > tablet/phone smallestWidthDp split.
- `IAdbService.GetPropAsync(ip, port, property)` — thin `adb shell getprop <name>` wrapper returning the trimmed value (or empty string on failure). Used by the Discovered panel to pre-fill a newly-added device's Name from `ro.product.model` when no name is remembered.
- **"Discovered on Network" panel** in Settings > Devices. After a Scan, mDNS-advertised devices that aren't yet registered show up in a dedicated table with IP, advertised ADB port, MAC (resolved via ARP — a ping pass refreshes ARP for any mDNS IPs not already in the table), and a one-click Add button. Clicking Add opens the Device form pre-filled with MAC, IP, port, and an initial Type of `AndroidPhone`; a background ADB probe then refines Type (`DetectDeviceKindAsync`) and auto-fills Name from `ro.product.model` when the name wasn't already restored from the delete-remembers-name flow.
- **Delete remembers the device's name.** When a device is deleted from Settings > Devices, its user-assigned name is stashed in the Settings table at `device-name-<mac>`. When the same MAC later reappears via mDNS scan and the user clicks Add, the form pre-fills Name from that stashed value before falling back to the ADB product-model probe — the user doesn't retype "My Phone" just because they deleted and re-added the device.
- **Network scanner modal** — `Settings › Devices` gained a new *Scan Network…* button that opens a full scanner modal (CIDR/IP/range subnet input, gateway auto-detect, four-state progress chip, live hit stream, Add buttons per hit, 2,048-host large-subnet warning, subnet syntax cheat sheet at `/help/subnets.html`).
- **ws-scrcpy-web deployment mode** — General Settings gained a Managed / External toggle. Managed keeps today's auto-spawn behaviour; External lets Control Menu point at a Docker container or remote host via URL. Dependency management respects mode: Install/Update hidden in External mode.
- **`NetworkScanService` (singleton)** — holds a `ClientWebSocket` to ws-scrcpy-web's `/ws-scan` endpoint, fans scan events to every Blazor circuit spectating a scan. Two browser tabs attaching mid-scan share one scan session with snapshot replay.
- **`SubnetParser`** — CIDR / IP / range parser mirroring ws-scrcpy-web's behaviour byte-for-byte, error verbiage included.
- **Device SerialNumber auto-fill** — when a user adds a device from the Discovered panel, `AddFromDiscovery` now probes `ro.serialno` alongside the existing kind and model probes and pre-fills the Serial Number form field. Users who type a value during the probe window keep their entry (empty-check guard, same pattern as the existing Name auto-fill). Existing registered devices without a serial stay unchanged — backfill is intentionally out of scope.
- **Iframe theme bridge** — Control Menu's theme now syncs bidirectionally with the embedded ws-scrcpy-web iframe on the `Android Power Tools` page. Toggling theme from either side (CM TopBar or ws-scrcpy-web's in-app toggle) updates both surfaces; reloading the page adopts CM's current theme. Requires bundled ws-scrcpy-web `v0.1.24-beta.5` or later.
- `wwwroot/js/scrcpyThemeBridge.js` — vanilla-JS interop module that bridges `themeManager` to ws-scrcpy-web's `postMessage` theme protocol. Listens for `ws-scrcpy-web:theme-ready` (replies with current theme) and `ws-scrcpy-web:theme-changed` (syncs CM to match). Exposes `window.scrcpyThemeBridge.notify(theme)` for `themeManager.set` to push outbound. Internal `settingFromIframe` guard prevents iframe → CM → iframe feedback loops.
- `themeManager.subscribe(callback)` and `themeManager.subscribeBlazor(dotnetRef)` — JS subscriber API in `wwwroot/js/theme.js`. The Blazor variant uses a numeric token (returned to .NET, passed back to `unsubscribeBlazor`) to avoid trying to marshal a JS function as `IJSObjectReference`.

### Changed
- **WizardDevices intro paragraph** now explicitly calls out the mDNS-only discovery limitation and directs older Android devices to Settings → Android Devices post-wizard. Substantive change in messaging, not behavior.
- **Settings sub-nav label "Devices" → "Android Devices"** (route identifier `devices` unchanged). Disambiguates from Cameras now that both modules have settings pages. Home page Settings card pill matches.
- **Android Devices `Discovery Interval` → `Liveness Interval`.** The setting was previously dead UI (saved but consumed by nothing). It now drives the new `AndroidLivenessHostedService`. Validation tightened: allowed values are `0` (disabled) or `300–3600` seconds (was `30–3600`). Existing saved values below `300` remain in storage but the UI will reject re-saves outside the new bounds. Same `discovery-interval` config key.
- **Camera periodic background loop refactored from subnet-scan to per-camera liveness.** The previous `CameraScanHostedService` invoked `ICameraScanService.StartScanAsync` on every periodic tick — auto-populating the Discovered panel without user intent. The replacement `CameraLivenessHostedService` only probes registered cameras directly; the Discovered panel is now exclusively a manual-scan surface. Old `cameras-scan-interval-minutes` config key (minutes) is replaced by `cameras-liveness-interval-seconds` (seconds) with the new bounds; legacy values left in storage are ignored.
- `CameraService.UpdateLastSeenAsync` and `DeviceService.UpdateLastSeenAsync` now fire their respective change-notifier so the Settings UI grid auto-refreshes Status/LastSeen when a liveness tick lands.
- **Local-Dependencies-Only audit (architectural sweep, 17 commits `f68f186..8be3f07`).** Eliminates every bare-name binary invocation that resolved through system `PATH`, replacing them with a new `IDependencyPathResolver` boundary that maps `(moduleId, name) → absolute path under dependencies/`. Per-commit detail:
  - `feat(deps)` Added `IDependencyPathResolver` interface + `DependencyNotInstalledException` (sealed) carrying `ModuleId`, `Name`, `ExpectedPath` for diagnostics.
  - `feat(deps)` Implemented `DependencyPathResolver` — looks up the module/dep, applies user override via `IConfigurationService.GetSettingAsync("dep-path-{name}")`, resolves through existing `InstallPathResolver`, appends `.exe` on Windows, throws `DependencyNotInstalledException` if the binary isn't present locally. Registered as Scoped (lifetime matches `IConfigurationService`; avoids captive-dependency anti-pattern).
  - `feat(deps)` Added `ResolvedExecutorExtensions.ExecuteResolvedAsync(this ICommandExecutor, IDependencyPathResolver, moduleId, name, args, …)` — the single supported entry point for invoking bundled binaries. Reserved the raw `ICommandExecutor.ExecuteAsync(string command, …)` overload for the documented OS-builtin allowlist (`docker`, `powershell`, `arp`, `ping`) via XML doc on both the interface and `CommandExecutor` class.
  - `refactor(adb)` Migrated all ~25 `_executor.ExecuteAsync("adb", …)` call sites in `AdbService` to a private `AdbAsync(args, ct)` helper that routes through the resolver. Constructor now takes `IDependencyPathResolver`. Includes a regression test that fails if a future change reintroduces a bare-name call.
  - `refactor(ws-scrcpy)` `WsScrcpyService.SpawnProcess` no longer uses `FileName = "node"`. `EnsureNodePathAsync` resolves the path via a fresh DI scope (existing `IServiceScopeFactory` pattern; service is a Hosted Singleton) and caches in `_nodePath`, called from `StartAsync` before the spawn lock is taken.
  - `refactor(jellyfin)` `JellyfinService` sqlite3 invocation routed through `ExecuteResolvedAsync` with module id `"jellyfin"`.
  - `refactor(deps)` `DependencyManagerService` `adb kill-server` (called before binary swap) routed through resolver; wrapped in `try/catch (DependencyNotInstalledException)` so first-time installs aren't blocked by "no adb to kill yet".
  - `refactor(deps)` Replaced external `tar` with `System.Formats.Tar.TarFile.ExtractToDirectoryAsync` over `GZipStream` — eliminates the last shell-out for archive extraction.
  - `refactor(deps)` Deleted `TryScanPathAsync`, `TryScanCommonLocationsAsync`, `GetCommonLocations` from `DependencyManagerService`. Stripped the system-PATH fallback branch from `GetInstalledVersionAsync`. `ScanForDependenciesAsync` now reports "Previously configured" or "Not found" — never "PATH" or "C:\platform-tools".
  - `fix(deps)` `IAdbService` registration changed from Singleton to Scoped to match `IDependencyPathResolver`'s Scoped lifetime — was a captive-dependency anti-pattern. Razor components and `ScanLifecycleHandler` (the only consumers) are already Scoped, so no consumer impact.
  - `fix(deps)` Removed the `Program.cs` PATH-prepend block that injected every `dependencies/*` subdirectory into the process `PATH` env var at startup. After the resolver migration nothing requires `PATH` to find bundled binaries, and leaving the prepend in place would silently mask any future bare-name regression.
  - `fix(cameras)` `Go2RtcService.FindExecutable` no longer scans every directory in system `PATH` as a fallback when the local install isn't found — the original audit missed this. Now resolves through `IDependencyPathResolver.ResolveAsync("cameras", "go2rtc")` via the existing `IServiceScopeFactory`; returns `null` on `DependencyNotInstalledException` (callers already null-check).
  - `docs(deps)` XML doc on `CommandExecutor` documents the OS-builtin allowlist policy explicitly so future contributors see the rule at the call site.
  - **Net behavior change for users:** if a tool was previously found on system `PATH` but never installed locally (e.g., adb installed via Android Studio outside `dependencies/`), it will now report "Not found" until installed via the dep manager or via a user-configured `dep-path-{name}` override.
- `MainLayout.razor` page-title switch gained a specific case for `/android-power-tools` that sits above the generic `path.StartsWith("android")` fallback. Without this the breadcrumb rendered "Android Devices" for the new route because the prefix match order is load-bearing.
- **Scan Network** (Settings > Devices) now queries mDNS first via `adb mdns services`, enriches each hit with MAC from the ARP table (pinging any mDNS IPs not yet in ARP to force resolution), and falls back to ARP-only refresh for devices that don't advertise over mDNS. When a device is matched via mDNS, Control Menu updates both its IP address AND its stored ADB port — previously the port would remain stale when a device's wireless debugging port changed (common on Android 11+ phones that rotate ports per session). Discovered unregistered devices are surfaced in a new panel below the registered-devices table (see Added). Toast reports `N of M registered device(s) found`, `K ADB port(s) updated from mDNS`, and `X new device(s) on network` as applicable.
- **Adding a new device auto-removes it from the Discovered panel.** Without this, the user would see the device they just added still listed as "available to add" until the next scan.
- `ScrcpyMirror.razor` now uses ws-scrcpy-web's `/embed.html?device=<udid>` wrapper URL (shipped 2026-04-17 in ws-scrcpy-web 1.0.0); the legacy `#!action=stream&udid=...&embed=true` hash routing has been removed upstream. Both `Inline=true` (inline iframe) and `Inline=false` (popup window) share the same URL — `/embed.html` is always in embed mode.
- `docs/TECHNICAL_GUIDE.md` — Stream URL section updated; Android Devices module description updated to reflect mDNS-first discovery; AdbService method table loses `GetUsbDevicesAsync` and `ResetTcpPortAsync`, gains `ScanMdnsAsync`; dashboard descriptions note the `DeviceKind` hint being passed to `ScrcpyMirror`.
- `docs/manual-test-checklist.md` — Section 5 (Settings > Devices) rewritten into subsections covering the registered-devices CRUD, Scan Network behavior, Discovered panel flow, and delete→rediscover name-memory path. ### Removed
- **Indexed 8-slot camera config.** Legacy `camera-{1..N}-name|ip|port` settings + `camera-{1..N}-username|password` secrets are purged on first launch via a one-shot, idempotent migration (marker key `cameras-legacy-purge-completed`). Pre-migration users will need to re-add their cameras through the new scanner. Pre-existing backups in `jellyfin-data/backups` (or any other user-data folders) are untouched.
- **`build.log`** — stale build output containing old `tools-menu` paths; added `build.log` to `.gitignore` to prevent future tracking.
- **`IScanLifecycleHandler.StashedNamesByMac`** and its backing implementation. The cache was populated by `PopulateStashedNamesAsync()` during `FinalizeScanAsync` (after `ScanCompleteEvent`), but `DiscoveredPanelRow` mounts during the scan on `ScanHitEvent` — the cache was always empty at row-mount time, so the fallback lookup in `ResolveInitialName()` never fired. Stashed-name restoration is handled correctly by `DiscoveredPanelRow.RunProbesAsync`, which reads `device-name-<mac>` directly via `IConfigurationService`. Handler ctor loses the `IConfigurationService` parameter (no longer needed). `DiscoveredPanel` / `DiscoveredPanelRow` lose the `StashedNamesByMac` parameter; `DeviceManagement.razor` drops the pass-through attribute. This also obsoletes two previously-planned follow-up items (B3 enumeration hardening and B4 parallelization of the stashed-name populate path) — the code they were going to harden no longer exists.
- `UsbSetupWizard.razor` and its stylesheet. The component existed to wire a freshly-flashed Android phone to wireless ADB over a USB cable (`adb tcpip <port>` → disconnect USB → connect over WiFi). ws-scrcpy-web's mDNS-based discovery replaces this flow end-to-end — phones advertise their ADB port over mDNS once wireless debugging is enabled once by the user, so the USB handshake dance is no longer necessary. The corresponding "Enable Wireless ADB" action-row on `PixelDashboard.razor` and the new-phone auto-trigger on `DeviceManagement.razor`'s Save flow have been removed. `IAdbService.GetUsbDevicesAsync` and `IAdbService.ResetTcpPortAsync` were deleted along with their implementations — both existed only to support the wizard.
- **Backup Directory row** from the Docker Compose parse-result table on Jellyfin Settings. Path is now configured (and editable) in the Logging, Backup & Retention section.
- **Backup & Retention** and **Managed Directories** standalone sections on Jellyfin Settings — merged into the new combined **Logging, Backup & Retention** section.
- **Managed mode for ws-scrcpy-web.** Control Menu no longer spawns or supervises the ws-scrcpy-web node process. `WsScrcpyService` is now an external-only URL holder (~30 lines). All process spawn/watch/restart/orphan-kill code removed.
- **Obsolete settings: `wsscrcpy-mode`, `ws_scrcpy_web_path`** (under module `android-devices`). Deleted on app startup by a one-time idempotent cleanup hosted service.

### Fixed
- **`fix(jellyfin)`** Jellyfin database backups landed in a stale `C:\Users\jscha\source\repos\tools-menu\…\jellyfin-data\backups\` path predating the `tools-menu → control-menu` repo rename. Root cause: `JellyfinService` persisted the runtime-derived backup directory into the `Settings` table (`jellyfin-backup-dir` row) at compose-parse time, then read that stored value on every backup — so the path captured at first run never updated when `AppContext.BaseDirectory` moved. Fix: stop persisting/reading the setting; `BackupDatabaseAsync` and `CleanupOldBackupsAsync` now call `OperationLogger.GetBackupDirectory()` directly, which always derives from the current `AppContext.BaseDirectory`. Removed the `SetSettingAsync("jellyfin-backup-dir", …)` writes in `JellyfinService.ParseComposeFileAsync` and `WizardJellyfin.razor`. The stale `Settings` row(s) are left in place (harmless once nothing reads them); pre-fix backup files at the old `tools-menu` path are user data and untouched. Also resolves the two-row `(ModuleId='jellyfin' / ModuleId=NULL)` divergence flagged in TODO item 11 — by removing the setting from the read path entirely, the divergence becomes irrelevant. `JellyfinServiceTests` updated: `BackupDatabaseAsync_CopiesFile` no longer mocks the dropped read; `CleanupOldBackupsAsync_RemovesOldFiles` rewritten to test against the real runtime backup directory with GUID-tagged filenames for cross-test isolation.
- **`fix(deps)`** Dependency install-path overrides survive repo renames. After last week's `tools-menu → control-menu` folder rename, the `dep-path-adb` and `dep-path-go2rtc` rows in `Settings` still held absolute paths to the old location. On launch the app reported those deps as missing; clicking *Update* re-downloaded the binaries to the **old** path, recreating `C:\Users\jscha\source\repos\tools-menu\` (with `platform-tools` and `go2rtc` subfolders) on every update cycle. Two-part fix: (1) `SetInstallPathAsync` now stores the override as a path **relative to `DepsRoot`** when the chosen path lives under it (e.g. `"platform-tools"` instead of `C:\...\dependencies\platform-tools`); `GetInstallPathAsync` and the local-version check resolve relative values against the current `DepsRoot` via the new `InstallPathResolver` helper. (2) `SyncDependenciesAsync` now runs `ValidateInstallPathOverridesAsync` at startup; any override whose resolved parent directory does not exist (rename / disk move) is logged and cleared so the module falls back to its default. New `Services/InstallPathResolver.cs` plus 9 unit tests in `tests/ControlMenu.Tests/Services/InstallPathResolverTests.cs` covering encode/decode round-trip, rename-survival, and parent-missing detection. The two stale rows in the live DB were deleted as a one-shot data cleanup, and the resurrected `tools-menu/` folder removed.
- **`fix(utilities)`** Icon Converter file picker silently dropped after a file was chosen — no filename appeared, Convert button stayed disabled, and the save dialog never opened. Two compounding bugs: (1) `file-picker.js` returned `{ name, bytes: Uint8Array }`, and a `Uint8Array` nested as a property of an interop result object does not round-trip cleanly through Blazor JS interop into a record's `byte[]` field; the deserialization exception aborted `PickFile` before the UI could update. (2) After fixing the deserialization by switching to base64 transport, the SignalR circuit dropped on file select with `Connection closed with an error` — Blazor Server's default `MaximumReceiveMessageSize` of 32 KB rejected even modestly-sized images. Fix: `file-picker.js` now base64-encodes the file (chunked to avoid `String.fromCharCode` stack overflow on large buffers) and returns `{ name, bytesBase64 }`; `IconConverter.razor`'s `FilePickerResult` record updated to `(string Name, string BytesBase64)`, decoded via `Convert.FromBase64String`; `PickFile` wrapped in try/catch so future interop failures surface as `_error` in the UI instead of silently terminating the handler; `Program.cs` raises `MaximumReceiveMessageSize` on the Blazor hub to 32 MB so high-res source images go through.
- **`fix(a5)`** Scrcpy settings modal probe was sending `action=PROBE_DEVICE` but ws-scrcpy-web expects `action=probe` — probes silently failed with WebSocket close code 4002 ("Unsupported request"), leaving the DB empty and all modals stuck on hardcoded h264/raw fallback defaults.
